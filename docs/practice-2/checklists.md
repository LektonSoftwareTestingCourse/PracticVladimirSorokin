# Чек-листы сервисов СМП

Ядро — в [test-design.md](test-design.md). Источники: [архитектура](../architecture.md), [API-контракт](../api-spec.md), ТЗ сервисов.

## 1. Окружение: Docker Compose, PostgreSQL, RabbitMQ

**Дымовые проверки**

- [ ] ENV-S01. Docker Compose запускает сервисы.
- [ ] ENV-S02. PostgreSQL принимает подключения, миграции выполнены.
- [ ] ENV-S03. RabbitMQ доступен, очереди и привязки созданы.

**Критический путь**

- [ ] ENV-K01. Карточные и транзакционные данные сохраняются после перезапуска сервиса.
- [ ] ENV-K02. Накопленные сообщения доставляются после восстановления потребителя.
- [ ] ENV-K03. Сервисы обрабатывают недоступность БД.
- [ ] ENV-K04. Карточные события публикуются после восстановления RabbitMQ.

## 2. Gateway

**Дымовые проверки**

- [ ] GW-S01. Gateway отвечает на health-check и показывает состояние зависимостей.
- [ ] GW-S02. API транзакций и поиска доступны.

**Критический путь**

- [ ] GW-K01. Gateway принимает запросы от обоих симуляторов.
- [ ] GW-K02. Gateway отклоняет запрос с ошибкой формата.
- [ ] GW-K03. Gateway передаёт поля платежа в Switch.
- [ ] GW-K04. Инициатор получает одобрение или отказ.
- [ ] GW-K05. Gateway обрабатывает недоступность Switch.
- [ ] GW-K06. Dashboard получает поиск и статистику через Gateway.

## 3. Switch

**Дымовые проверки**

- [ ] SW-S01. Switch отвечает на health-check.
- [ ] SW-S02. Маршруты BIN загружены.

**Критический путь**

- [ ] SW-K01. Switch выбирает маршрут и issuerId по BIN.
- [ ] SW-K02. Switch обрабатывает BIN без маршрута.
- [ ] SW-K03. Запрос доходит до Authorization, ответ возвращается в Gateway.
- [ ] SW-K04. При недоступном Authorization выполняются предусмотренные повторы.
- [ ] SW-K05. Switch публикует транзакцию и получает подтверждение RabbitMQ.
- [ ] SW-K06. В журнал передаются исходные сумма, идентификаторы и решение.
- [ ] SW-K07. Switch обрабатывает задержку потребителя Logger.

## 4. Terminal Simulator

**Дымовые проверки**

- [ ] TERM-S01. Terminal Simulator доступен.
- [ ] TERM-S02. Симулятор получает пул карт из CMS с пагинацией.

**Критический путь**

- [ ] TERM-K01. Платежи отправляются через Gateway.
- [ ] TERM-K02. Симулятор считает одобренные и отклонённые платежи.
- [ ] TERM-K03. Симулятор обрабатывает пустой пул карт.
- [ ] TERM-K04. Удалённые карты исключаются из пула.
- [ ] TERM-K05. Генерация останавливается по команде.
- [ ] TERM-K06. Симулятор обрабатывает недоступность Gateway или CMS.

## 5. Merchant + Acquirer Simulator

**Дымовые проверки**

- [ ] MERCH-S01. Merchant + Acquirer Simulator доступен.
- [ ] MERCH-S02. Предусмотренные сценарии запускаются.

**Критический путь**

- [ ] MERCH-K01. Платежи проходят через Gateway.
- [ ] MERCH-K02. MCC выбирается по сценарию или явному списку кодов.
- [ ] MERCH-K03. В платежах передаются merchantId и acquirerId.
- [ ] MERCH-K04. Симулятор рассчитывает комиссию эквайрера.
- [ ] MERCH-K05. Симулятор считает одобрения и отказы.
- [ ] MERCH-K06. Симулятор обрабатывает недоступность Gateway.

## 6. Transaction Logger

**Дымовые проверки**

- [ ] LOG-S01. Logger и поиск транзакций доступны.
- [ ] LOG-S02. Потребитель подключён к очереди transaction-log.

**Критический путь**

- [ ] LOG-K01. Logger сохраняет одобренные и отклонённые транзакции из RabbitMQ.
- [ ] LOG-K02. Транзакция находится по RRN.
- [ ] LOG-K03. Поля транзакции сохранены, PAN замаскирован.
- [ ] LOG-K04. Повторная доставка не создаёт дубликат.
- [ ] LOG-K05. Фильтры, пагинация и статистика работают на сохранённых данных.
- [ ] LOG-K06. Новая транзакция приходит WebSocket-клиентам.
- [ ] LOG-K07. После восстановления Logger обрабатывает накопленные сообщения.

## 7. Bin Lookup

**Дымовые проверки**

- [ ] BIN-S01. Bin Lookup доступен.
- [ ] BIN-S02. Для зарегистрированного BIN возвращаются данные эмитента.

**Критический путь**

- [ ] BIN-K01. Данные эмитента соответствуют BIN.
- [ ] BIN-K02. Сервис обрабатывает неизвестный BIN.
- [ ] BIN-K03. При серверной ошибке запрос повторяется.
- [ ] BIN-K04. При недоступном Bin Lookup авторизация использует issuerId из Switch.

## 8. Notification Service

**Дымовые проверки**

- [ ] NOTIF-S01. Notification Service и список уведомлений доступны.
- [ ] NOTIF-S02. Потребитель подключён к очереди card-notifications.

**Критический путь**

- [ ] NOTIF-K01. События создания, изменения и удаления карты поступают в сервис.
- [ ] NOTIF-K02. Тип и данные события сохраняются.
- [ ] NOTIF-K03. Список уведомлений и пагинация соответствуют сохранённым событиям.
- [ ] NOTIF-K04. После восстановления сервис обрабатывает накопленные события.

## 9. Web Dashboard

**Дымовые проверки**

- [ ] WEB-S01. Страница Dashboard загружается и подключается к API.
- [ ] WEB-S02. Dashboard подключается к WebSocket Logger.

**Критический путь**

- [ ] WEB-K01. Одобренные и отклонённые платежи отображаются.
- [ ] WEB-K02. Новая транзакция обновляет таблицу и статистику.
- [ ] WEB-K03. Фильтры и просмотр выбранной транзакции работают.
- [ ] WEB-K04. Суммы отображаются, PAN замаскирован.
- [ ] WEB-K05. Dashboard обрабатывает отсутствие транзакций.
- [ ] WEB-K06. WebSocket переподключается после разрыва.
- [ ] WEB-K07. Dashboard показывает недоступность API.

## 10. Классы верхнего уровня

| Компонент | Классы | Проверки |
|---|---|---|
| Gateway | Корректный запрос / ошибка формата; Switch доступен / недоступен | GW-K01…05 |
| Switch | BIN с маршрутом / без маршрута; Authorization доступен / недоступен | SW-K01…04 |
| Terminal Simulator | Пул непустой / пустой; генерация включена / остановлена; зависимость доступна / недоступна | TERM-K01…06 |
| Merchant + Acquirer | Одобрено / отклонено; MCC из сценария / задан явно; Gateway доступен / недоступен | MERCH-K01…06 |
| Transaction Logger | Одобрено / отклонено; новая / повторная доставка; потребитель доступен / восстановлен | LOG-K01…07 |
| Bin Lookup | Известный / неизвестный BIN; сервис доступен / недоступен | BIN-K01…04 |
| Notification Service | Создание / изменение / удаление; получение сразу / после восстановления | NOTIF-K01…04 |
| Dashboard | Данные есть / данных нет; WebSocket подключён / разорван; API доступен / недоступен | WEB-K01…07 |
| PostgreSQL, RabbitMQ | Доступны / недоступны; сообщения обработаны / накоплены | ENV-S01…03, ENV-K01…04 |
